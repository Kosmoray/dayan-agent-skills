# False-positive control

## Principle

Pretty output, fluent language, and passing structure checks are signals, not proof that the work is useful, safe, or true.

## Apply it

1. List the signals that could look like success while the result is still wrong.
2. Separate structure checks from outcome checks.
3. Add one attractive-but-rejected fixture.
4. Require evidence that would change a skeptical reviewer’s mind.
5. Keep the non-claim boundary visible beside the pass result.

## Failure pattern

The method has failed when a polished artifact is accepted because it looks complete, while missing facts, authority, usability, or real-world evidence remain unchecked.
